# Waveform browser IAM 5 contexts

Each saved browser context contains one verified Carbon or Silicon account, one organization, and its production or specific testing environment. The gateway retains independent encrypted slots when adding other accounts or sandboxes. The account selector switches an explicit saved context through `POST /api/session/context`; the existing production/testing switch remains available. The public snapshot includes context IDs and display information, never credentials or application secrets.

An IAM login is verified without reusing the previous organization's header. The returned account determines the new slot's organization. Both ordinary account verification and refresh reject actor or organization drift. Resource calls remain bound to their original slot while account changes serialize; stale tabs and pending approval completions receive `409 workspace_changed` before forwarding work. Caller organization overrides are rejected. Saved slots survive gateway restart, and signing out removes only the selected context. Legacy persisted bearers without a context ID require a fresh IAM login.

The browser API captures the context when speech, history, settings, and Briefcase approval views mount. It rejects obsolete requests and late results after a workspace change. Ordinary refresh preserves the mounted view. Returning to a saved workspace restores that workspace's non-secret speech draft in memory; provider keys and pending approval codes are cleared when leaving it. Job results, provider credentials, and pending speech requests are never moved between workspaces.

Briefcase approval uses Waveform's existing provider-owned storage authorization routes. Start and completion keep stable retry keys, completion validates the authorization ID and state, and a 412 requires a new permission review. Consent links must use HTTPS without embedded credentials. Approval does not submit speech: the user explicitly retries the original request with its original request ID and idempotency key. Cancel clears the pending approval and preserves the editable text or source URL.

Run `npm test`, `npm run check`, and `npm run build` in `frontend`. Coverage includes saved same-organization accounts, Carbon/Silicon identities, multiple sandboxes, encrypted persistence/restart, immutable identity verification and refresh, stale mutations, consent response binding, bundled browser request behavior, and legacy-session invalidation. Live IAM 5 and Briefcase approval acceptance remains required before release.
